# Мирас — легенды рядом

Основа хакатонной игры о татарской культуре. Су анасы выдаётся как стартовый хранитель. Игрок знакомится с историей босса и побеждает его в PvE-испытании. Только после победы хранитель попадает в коллекцию.

**Frontend:** React + TypeScript + Vite, Tailwind CSS, Motion, React Router, Zustand. **Backend:** C# / ASP.NET Core 10 + EF Core. **БД:** PostgreSQL. PvE рассчитывается сервером и сохраняется в PostgreSQL; автономный TypeScript-движок нужен для быстрого показа без backend.

## Быстрый запуск

Требуется Node.js 24 LTS. Для backend — .NET SDK 10.

```bash
npm ci
npm run dev
```

Открыть http://localhost:5173. Без переменных окружения включается автономное демо: API и аккаунты не нужны, прогресс хранится в localStorage. Сбросить его можно в «Мой путь». Это режим для демонстрации: пользователь может изменить локальные часы и данные.

## Запуск с настоящим C# API

Первый терминал:

```bash
dotnet run --project backend/Miras.Api
```

API: http://localhost:5080, проверка: http://localhost:5080/health. API требует PostgreSQL и сам применяет EF Core migrations. Для стандартной локальной строки подключения сначала подними `db` через Compose. Гостевой токен хранится в браузере, а в БД сохраняется только его SHA-256 хеш.

Скопировать `.env.example` в `.env.local` и указать:

```dotenv
VITE_API_URL=http://localhost:5080
```

Во втором терминале:

```bash
npm run dev
```

После изменения `.env.local` перезапустить Vite. Серверный и автономный прогресс разделены. В серверном режиме браузер отправляет только действия; состав команды, поимка и здоровье рассчитываются C#.

## PostgreSQL через Docker

```bash
docker compose up --build
```

Поднимутся PostgreSQL на `127.0.0.1:54329` и API на `127.0.0.1:5080`. Данные хранятся в Docker volume. Frontend запускается отдельно, с `VITE_API_URL` выше. Пароль в compose предназначен только для локальной разработки. Остановить: `docker compose down` (данные сохранятся).

Для своей PostgreSQL-базы передать API конфигурацию `ConnectionStrings__PostgreSql` (через окружение или .NET user-secrets), например `Host=localhost;Port=54329;Database=miras;Username=miras;Password=...`.

## Что реализовано

- Четыре персонажа: Шурале, Сююмбике, Су анасы, Керемль.
- Су анасы сразу доступна на первом уровне. История открывает PvE-испытание; победа даёт персонажа первого уровня.
- Неудача закрывает следующую попытку на 24 часа; перезагрузка страницы не снимает ограничение.
- Real-time PvE до 90 секунд: команда до трёх хранителей, переключение активного бойца, три позиции, автоматическая обычная атака и два активных умения. Опасная позиция и время до удара показаны заранее.
- Восемь лорных умений: удержание без потери управления, отражение снарядов, морок, щиты, ослабление атаки и закрытие позиции. Полное описание — в `docs/BATTLE_DESIGN.md`.
- Победа над боссом добавляет его в коллекцию. Внутриигровой валюты и прокачки в текущем прототипе нет.
- Активный бой сохраняется. При скрытии вкладки или разрыве связи дольше 1,5 секунды бой ставится на паузу; награда и поимка применяются ровно один раз.
- Мобильная навигация, обратная связь ошибок, поддержка reduced motion.
- Схематичная карта и авторские SVG-персонажи. PixiJS рисует арену и эффекты; интерфейс и персонажи остаются доступными DOM/SVG-элементами. При недоступном WebGL бой работает с упрощённой сценой.

## Как устроен бой

Бой проходит в реальном времени и длится не больше 90 секунд. Игрок берёт в команду от одного до трёх собранных хранителей, но одновременно на арене находится один активный персонаж.

- Арена разделена на три позиции: слева, по центру и справа. Нажми на позицию или используй клавиши `1`, `2`, `3`, чтобы переместиться.
- Обычная атака выполняется автоматически, когда активный персонаж находится на одной позиции с боссом.
- У каждого персонажа два активных умения. Кнопки `Q` и `E` используют их, после чего начинается перезарядка.
- Опасные атаки босса заранее подсвечивают позиции и показывают время до удара. Можно уйти, применить защитное умение или использовать эффект персонажа для контратаки.
- Хранителей можно переключать во время боя. Их здоровье, эффекты и перезарядки сохраняются. Если активный персонаж повержен, следующим автоматически выходит живой участник команды.
- Противник всегда один: босс, которого игрок хочет получить. Его здоровье и урон масштабируются по размеру выбранной команды: один герой получает щадящую версию босса, два — усиленную, три — полную.
- Победа наступает, когда здоровье босса заканчивается. Поражение — когда повержена вся команда или закончилось время.
- Босс автоматически становится слабее для команды из одного или двух персонажей, поэтому первый захват проходим стартовой Су анасы первого уровня.

Главная связка Су анасы: `Золотой гребень` удерживает босса на позиции, а `Обратная волна` снимает удержание с самой Су анасы, наносит урон и отражает летящие снаряды. Удержание запрещает только перемещение — умения остаются доступными.

Первый игровой цикл: получить Су анасы → прочитать историю Шурале → вызвать его на бой → победить → получить Шурале в коллекцию.

## NFC

Записать на метку **NDEF URI с HTTPS-ссылкой**. Web NFC не требуется: ОС открывает адрес в браузере.

| Персонаж | Путь                   |
| -------- | ---------------------- |
| Шурале   | `/encounter/forest-01` |
| Сююмбике | `/encounter/tower-01`  |
| Су анасы | `/encounter/water-01`  |
| Керемль  | `/encounter/stone-01`  |

Например: `https://YOUR-DOMAIN/encounter/forest-01`. Копирование ссылок есть на странице «Мой путь». На телефоне нужен публичный HTTPS-домен: `localhost` с ноутбука ему недоступен. После публикации проверить метку реальным Android/iPhone.

**Обычная URL-метка не доказывает физическое присутствие:** ссылку можно переслать. Карта условная, координаты и GPS не подключены. Размещение настоящих меток и античит — следующий этап.

## Облако: Vercel + C# hosting + Supabase

1. Создать Supabase-проект, включить Anonymous Sign-ins в Auth.
2. Применить `backend/schema.sql` в PostgreSQL через SQL Editor или psql. Таблица имеет RLS и не доступна клиентским `anon`/`authenticated`; браузер работает через API.
3. Разместить C# API на хостинге, поддерживающем .NET или Docker. Dockerfile: `backend/Dockerfile`, контекст — корень репозитория, порт 8080. **Vercel здесь обслуживает только frontend.**
4. В окружении API настроить:

```dotenv
ASPNETCORE_ENVIRONMENT=Production
ConnectionStrings__PostgreSql=YOUR_POSTGRES_CONNECTION_STRING
Cors__Origins__0=https://YOUR_FRONTEND_DOMAIN
```

Для сетевого подключения к Supabase PostgreSQL использовать строку подключения с SSL-параметрами из панели проекта. Текущая ветка использует собственную гостевую сессию C# API. Проверка Supabase Auth JWT остаётся отдельной задачей перед production.

5. Импортировать репозиторий в Vercel: framework Vite, build `npm run build`, output `dist`, Node 24. Задать:

```dotenv
VITE_API_URL=https://YOUR_CSHARP_API_DOMAIN
```

`VITE_*` доступны всем посетителям. Строка подключения PostgreSQL и service_role key **никогда** не должны там находиться. Service role key приложению не нужен. SPA rewrite для прямых NFC-ссылок уже в `vercel.json`.

Привязка email/OAuth и восстановление доступа ещё не реализованы. Supabase Storage не нужен для текущих SVG; можно подключить позже для иллюстраций и аудио.

## API и данные

- `GET /health` — проверка процесса.
- `POST /api/auth/guest` — локальный гостевой вход, только Development без Supabase.
- `POST /api/game` + `Authorization: Bearer TOKEN` — команда игры.

```json
{"type":"sync"}
{"type":"capture","characterId":"shurale","tagId":"forest-01","answers":[0,1,2]}
{"type":"pveStart","characterId":"su-anasy","target":"shurale","mode":"encounter"}
{"type":"pve","battleId":"ID_FROM_SERVER","action":"poll","input":{"kind":"move","lane":0}}
{"type":"pve","battleId":"ID_FROM_SERVER","action":"poll","input":{"kind":"skill","slot":1}}
```

Указанные JSON-объекты — отдельные примеры запросов. Ответ: `{ "progress": { ... }, "outcome": "ready" | "failed" | null }`. Ошибки: `{ "error": "..." }`, HTTP 400/401/409. После конфликта 409 обновить состояние.

Пользователи, коллекция, встречи, вопросы и бои хранятся в отдельных EF Core таблицах. Снимок real-time боя лежит в `PveBattles.StateJson` (`jsonb`), а `Version` используется как concurrency token. Награда, завершение встречи и добавление в коллекцию сохраняются одной транзакцией `SaveChanges`.

## Структура

```text
src/pages/                 Карта, встреча, коллекция, бой, профиль
src/components/            Навигация, SVG-иллюстрации, PixiJS-сцена
src/store/game.ts          Zustand + разделение demo/API
src/lib/api.ts             HTTP-клиент C# API, гостевой и Supabase Auth
shared/characters.ts       Истории, вопросы, отображаемые характеристики
shared/pve/                TypeScript PvE-движок и единый баланс демо
shared/demo.ts             Локальные игровые команды
shared/quiz.ts             Демо-ответы; не средство защиты
backend/Miras.Api/         ASP.NET Core, серверный GameEngine, EF Core, Auth
backend/Miras.Api.Tests/   Тесты правил, API и конкурентных изменений
backend/schema.sql        Начальная PostgreSQL-схема и RLS
```

C# PvEEngine — источник истины в серверном режиме. TypeScript-движок поддерживает автономное демо; тесты фиксируют одинаковые ключевые правила. Ответы викторины видны в демо-бандле/исходниках: автономный режим не рассчитан на защиту от изучения клиента. В серверном режиме клиент не может напрямую записать валюту или коллекцию.
